# intent_MILEAGE — учёт пробега авто в решении по заявке

ID задачи: `MILEAGE`. Собрано после интервью Grill Me — лог: `grill_MILEAGE.md`.

## 1. Замысел

В расчёт решения по заявке добавляется проверка пробега авто: при пробеге 400 000 км и выше заявка не может получить автоподтверждение — при LTV-approve решение понижается до `review` (ответ в интервью, Вопрос 1). Заявка без пробега (отсутствующее поле, null или пустая строка) — невалидная (ответ в интервью, Вопрос 3). Каждое решение сопровождается кодом причины (LTV-обоснование или высокий пробег); причина возвращается в API-ответе и хранится в БД (ответ в интервью, Вопросы 4–5). Фронтенд не меняется (ответ в интервью, Вопрос 6).

## 2. Зачем

Сегодня решение считается только по LTV — пробег в него не входит (код: `backend/src/Domain/DecisionEngine.php`, `backend/src/Domain/AssessmentService.php`). Авто с очень большим пробегом при низком LTV автоматически одобряются. Проверка закрывает этот пробел: такие заявки уходят на ручную проверку вместо автоподтверждения. Коды причин дают видимость, почему решение вынесено (ответ в интервью, Вопросы 4–5).

## 3. Constraints

- Пробег 400 000 км и выше при LTV-approve → `review`; 399 999 км и ниже — решение по LTV без изменений. — ответ в интервью (Вопрос 1)
- Правило только понижает `approve` → `review`; LTV-`review` и LTV-`reject` не перекрываются и не смягчаются («худшее из правил»). — ответ в интервью (Вопрос 2)
- Решение по LTV (approve / review / reject по порогам, значения — см. `rules.php`) остаётся основой расчёта. — код: `backend/src/Domain/DecisionEngine.php`
- Заявка без пробега невалидна: отсутствующее поле/null отклоняются и сегодня (код: `backend/src/Domain/ApplicationValidator.php`); пустая строка, которая сейчас считается нулевым пробегом (код: `backend/src/Domain/ApplicationValidator.php`), после изменения тоже отклоняется с 422 (код: `backend/src/Http/ApplicationController.php` — код статуса невалидной заявки). — ответ в интервью (Вопрос 3)
- Код причины есть у каждого решения: LTV-обоснования (approve / review / reject) и высокий пробег. — ответ в интервью (Вопрос 5)
- Причина решения возвращается в API-ответе и хранится в БД. — ответ в интервью (Вопрос 4)
- Существующий жёсткий потолок пробега при валидации: заявки с пробегом выше потолка отклоняются до расчёта решения (значение — см. `rules.php`). — код: `backend/src/Domain/ApplicationValidator.php`, `backend/config/rules.php`
