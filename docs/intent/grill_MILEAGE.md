##  Вопросы
# Вопрос 1
Граница «не больше 400 000 км»: 400 000 включительно (решение по LTV, т.е. при хорошем LTV — approve), а review только с 400 001? Или 400 000 уже даёт review?
400 000 → уже review
# Вопрос 2
Как правило сочетается с решением по LTV: если LTV уже дал review или reject, а пробег выше порога — оставляем худшее (review/reject без изменений), или высокий пробег перекрывает всё в review?
Только понижение (Recommended)
# Вопрос 3
Пустая строка в поле пробега сегодня превращается в 0 км и проходит валидацию. Оставляем это вне scope задачи MILEAGE или чиним здесь же?
Чинить до 422 в этой задаче
# Вопрос 4
Нужно ли возвращать/хранить причину review («высокий пробег») для андеррайтера и фронтенда, или rule меняет только само решение?
Причина в API и в БД
# Вопрос 5
Поле причины решения заполняем только при review из-за пробега (остальные — NULL), или вводим коды причин для всех решений (включая LTV-review/reject)?
Для всех решений
# Вопрос 6
Показывать ли причину решения на фронтенде (форма заявки), или причина нужна только в API и БД?
Нет, фронт не трогаем

Граница строгая: review начиная ровно с 400 000 км (399 999 — ещё по LTV).
Семантика: только понижение approve → review; LTV-review и LTV-reject не перекрываются и не смягчаются.
